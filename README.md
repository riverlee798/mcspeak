# mcspeak · 麦麦替你说

**帮不会中文的外国人在中国麦当劳点餐。** 用他的母语推荐和改单，自动算券，生成「中文在上、他的语言在下」的双语卡片——柜台卡、待付款卡、取餐卡、地图卡。

> 参赛作品：**麦当劳程序员创意开发大赛** · **WaytoAGI 1024 用餐赛道**
> 形态：WorkBuddy Skill（本仓库即技能目录）· 底层能力：麦当劳中国官方 MCP（`mcd-mcp`）

---

## 一句话

外国人走进麦当劳，用母语说完"我要一个不辣、不要生菜、不要冰的可乐"，然后举着一张卡片给店员看，就能吃到。

---

## 要解决的问题

**很多外国人走进麦当劳，在柜台前因为说不出来而离开。**

- 菜单、点餐机、订单页全是中文；麦当劳 App 只有中英文，不会英语的人（阿拉伯语、俄语、西语游客）连"去支付""待取餐"都不认识。
- 点餐要求中文交互：说"堂食还是外带""要加大的吗""要不要加 2 块换购"，一句听不懂就卡死。
- 饮食限制更危险：清真、过敏、不吃猪肉，说错一次就是真问题。
- 现有翻译 App 只能翻句子，**不认识麦当劳的菜单结构**：不知道套餐能换什么、饮料能不能去冰、券能不能用、取餐码在哪看。

mcspeak 不做"翻译"，做**点餐这件事本身**：它真的会调麦当劳的接口下单、真的会算券、真的会生成店员看得懂的卡片。

## 核心功能

| 功能 | 说明 |
|---|---|
| **母语推荐和换餐** | 从 93 个商品里按口味、预算、饮食限制筛 3–5 个，按「① 主食/套餐 ② 小食 ③ 饮料」逐格给出，每格附 2 个可换选项和差价 |
| **真实改单** | 去生菜、去冰、去芝士、去酱——用运行时 `query-meal-detail` 的 `selectedKey`/`unselectedKey` 写进订单参数，**不是写在纸上** |
| **自动算券** | 领券 → 查本店可用券 → 逐张挂到商品行试算 → 失败就摘掉重算 → 报实付最低价；券没生效就如实说"X 月 X 日起可用，今天按原价" |
| **饮食限制（按名称）** | 清真三档过滤、含猪肉直接排除、过敏只做风险提示；**明确说明麦当劳中国不提供清真认证、接口没有过敏原数据** |
| **双语配对卡片** | 四张卡：柜台卡（给店员指）、待付款卡（App 优先）、取餐卡（超大取餐码）、地图卡（给出租车司机）。每块中文在上、他的语言在下，横屏自动两栏对齐 |
| **线上下单** | 到店自取，`calculate-price` 核价 → `create-order` → App「去支付」或支付链接 → `query-order` 拿取餐码 |
| **导航** | 高德（首选）/ 腾讯（备选）/ 谷歌（注明国内偏移）+ 内联二维码 + 给司机的中文地址 |

## 真实测试记录

**2026-10-24，济南，麦当劳济南山大路(成大高科)餐厅。**

一位阿拉伯语用户完整走通全流程：用阿拉伯语说出需求 → mcspeak 推荐并改单（去生菜、可乐去冰）→ 线上下单 → 在麦当劳 App 里用黄色「去支付」按钮完成付款 → **生成双语取餐卡，到柜台出示并成功取餐一份经典麦旋风**。

付款后按 App 实际顺序记录了完整状态链路：**待支付 → 确认中 → 配餐中 → 待取餐 → 订单已准备完毕**，并发现取餐码在 App 上显示为「订单号」——这条直接改掉了卡片的写法。

同期还验证了完整失败路径：未付款订单 15 分钟后自动关闭（状态「订单已取消」），以及券未到生效日时 `calculate-price` 直接报 `600012`（整单失败而非静默忽略）。

> 出于隐私，订单号、取餐码、支付单号、支付链接一律不公开；`references/samples/` 中的真实返回已做脱敏（见[安全检查](#安全检查)）。

## 安装方法

### 1. 配置麦当劳 MCP 连接器（**先做这一步，两种安装方式都需要**）

在 WorkBuddy 的**连接器管理**里添加 `mcd-mcp`（麦当劳中国官方 MCP），或编辑 `~/.workbuddy/mcp.json`：

```jsonc
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "http",
      "url": "${MCD_MCP_URL}",
      "headers": { "Authorization": "Bearer ${MCD_MCP_TOKEN}" }
    }
  }
}
```

`${MCD_MCP_URL}` / `${MCD_MCP_TOKEN}` 换成你自己的连接地址与令牌（**不要把真实 Token 写进仓库**）。
仓库里的 `mcp-config.example.json` 就是这份模板，只含占位符。填好后重启 WorkBuddy，连接器状态显示已连接再装技能。

> 为什么需要它：菜单、门店、券、下单、订单状态、取餐码全部来自这套官方接口，没有它 mcspeak 只能做翻译。

### 2. 安装技能

技能包在 **`dist/mcspeak-skill.zip`**（146 KB / 41 个文件，只含运行时需要的部分：`SKILL.md`、`references/`（含已脱敏 samples）、`templates/`、`scripts/`、`data/README.md`）。
`SKILL.md` 在 zip 根目录，解压后它必须直接位于技能目录第一层。

**方式 ① WorkBuddy 界面（推荐）**

> **技能 → 添加技能 → 上传技能** → 选择 `dist/mcspeak-skill.zip` → 安装完成后在技能列表里确认出现 **mcspeak**。

**方式 ② 手动解压**

```bash
# Windows（PowerShell）
Expand-Archive -Path dist\mcspeak-skill.zip -DestinationPath "$env:USERPROFILE\.workbuddy\skills\mcspeak" -Force

# macOS / Linux
mkdir -p ~/.workbuddy/skills/mcspeak
unzip -o dist/mcspeak-skill.zip -d ~/.workbuddy/skills/mcspeak
```

装完的目录应该是这样（`SKILL.md` 在第一层，不再多套一层文件夹）：

```
~/.workbuddy/skills/mcspeak/
├── SKILL.md                 技能主文件（S1–S16 全流程）
├── references/              6 个参考文件 + 24 个已脱敏样本
├── templates/               4 个卡片模板（单文件 HTML，离线可用）
├── scripts/                 render_card.py · demo.py · check_privacy.py
└── data/README.md           运行时偏好目录说明（profile.json 首次写入时创建）
```

> 从源码仓库直接用也可以：把整个仓库（`examples/`、`docs/` 是给评审看示例的，可留着）复制到
> `Windows: C:\Users\<you>\.workbuddy\skills\mcspeak` / `macOS: ~/.workbuddy/skills/mcspeak`。
> 这只影响体积，不影响运行。

### 3. 验证

在 WorkBuddy 新开对话，用任意非中文语言说一句：

```
Макдональдс рядом, помоги заказать
```

或直接说 `McSpeak`。技能列表里应能看到 **mcspeak**。

## 限制说明（请务必先读）

1. **清真只按名称过滤**：接口没有配料表、没有清真标识。mcspeak 只排除名称里含猪肉/培根/猪柳的商品，**不做任何认证背书**，也**不承诺**门店无交叉接触。麦当劳中国**没有提供清真认证信息**。
2. **到店订单不能加备注**：`remark` 字段只在外送场景生效。线上点餐加不了"少放酱""多加洋葱"这类自由文本，只能改官方支持的特调项；做不到的会写进柜台卡的"顾客请求"，并建议改去柜台点。
3. **接口没有过敏原信息**：无麸质、坚果、奶、蛋、大豆等数据一律没有。mcspeak 只按名称做**风险提示**并给一张"我对 XX 过敏，请问这个里面有 XX 吗？"的中文卡，**绝不输出"安全"结论**。
4. **没有门店经纬度**：实测 `query-nearby-stores` 返回 `longitude/latitude` 恒为 `0.0`，所以地图卡用"店名+城市"搜索链接，不显示坐标。
5. **没有地铁/公交数据**：地图卡只给「问店员的中文问句」+「地图里怎么搜」，**不给具体站名和线路**，避免编造。
6. **状态以文字为准，码只做辅助**：实测主链路 `待支付 → 确认中 → 配餐中 → 待取餐 → 订单已准备完毕`，另有 `订单已完成=40`、`订单已取消=60`；**中间三态的数字码没取到**，遇到未知状态只意译、不猜。
7. **App 上的「订单号」就是取餐码**：接口叫 `pickupCode`，App 显示为「订单号」。卡片上会写明这一句，避免访客把长串「订单编码」报给店员。
8. **卡片内置 en / ru / ja / ar 四种文案**，其他语言由模型**当场翻译**后通过 `--tr` 注入（脚本缺译会报错，不会偷偷输出英文）：`--dump-keys ko` → 翻译 → `--tr ko.json --lang ko`。
9. **卡片要"接力"到手机**：在电脑上跑 Skill 时，卡片 HTML 生成在电脑上，需要局域网地址 / GitHub Pages / 微信文件传输助手才能到手机。**对话里永远同时给一份「中文 + 用户语言」的纯文本版**，截图即可用。

## 后续计划

1. **扫码把卡片接力到手机**：电脑上生成后直接出一个二维码，手机扫一下就在本地打开——不再依赖局域网 IP 和防火墙（现在最烦的就是这个）。
2. **网页版**：扫码即用，不装 WorkBuddy 也能点（复用同一套模板与渲染脚本）。
3. **多 Agent 支持**：除 WorkBuddy，适配 **Claude Code / Codex** 等支持 MCP 的 Agent。
4. **补全卡片文案语言**：目前卡片覆盖 en/ru/ja/ar，扩到韩/法/西/德。
5. **状态码补测**：把 `确认中 / 配餐中 / 待取餐 / 订单已准备完毕` 的数字码逐个记录下来。
6. **菜单标注扩充**：把 93 个商品的 `modification` 全量探测一遍，让"可去掉的配料"不再是快照。
