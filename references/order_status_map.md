# order_status_map.md — 订单状态映射 + 麦当劳 App 界面词汇对照

> 数据来源：2026-10-24 对门店 `3350020` 的真实下单实测（`samples/17`、`18`、`19`、`20`）+ 用户提供的 App 截图实况。
> **工具文档里的 `status` 枚举与实测不符，一律以本表「实测」列为准。**

---

## 1. 订单状态总表

| 中文状态（`orderStatus`） | `status` 码 | 含义 | 用户该做什么 | 实测情况 |
|---|---|---|---|---|
| **待支付** | `10` | 订单已创建，**还没付钱**，有 15 分钟付款时限 | 立刻点「去支付」扫码付款；不想要就点「取消订单」 | ✅ **实测**（`samples/17`、`18`） |
| **请取餐**（备餐完成） | 待校正 | 餐已做好，柜台/取餐柜可以拿了 | **凭取餐码去柜台取餐**，出示取餐卡 | ⏳ **待校正**（本轮没付款，未测到） |
| 配餐中 / 制作中 | 待校正 | 已付款，后厨在做 | 在旁边等，看屏幕叫号 | ⏳ 待校正 |
| 配送中 | 待校正 | 外送骑手在路上（本 Skill 不做外送） | — | ⏳ 未测（外送场景） |
| **订单已完成** | `40` | 订单结束，餐已取走 | 不需要操作；可评价 | ✅ **实测**（`samples/20`，历史单） |
| **订单已取消**（超时未付） | `60` | 超过 `expirePayTime` 未付款，系统**自动关闭**（不叫"已过期"） | 重新下单；不会扣款 | ✅ **实测**（`samples/19`） |
| 订单已取消（用户主动取消） | 待校正 | 访客点了「取消订单」 | 钱会原路退回；需重新下单 | ⏳ **待校正**（与超时取消是否同为 `60` 未知） |
| 已评价 | 待校正 | 已提交评价 | 不需要操作 | ⏳ 未测 |
| 退款中 / 已退款 | 待校正 | 取消后的退款流程 | 等 1–7 个工作日 | ⏳ 未测（未见退款字段） |

> **码值体系的重大发现**：实测用的是 `10 / 40 / 60` 这套码（10 待支付、40 已完成、60 已取消），
> 而工具文档写的是 `1/2/4/6/7/8/10`（1 待支付、2 配餐中-已支付、4 配送中、6 已完成、7 已取消、8 已评价、10 配餐中-餐厅确认配餐中）——**两套完全不合**。
> 文档那一套很可能是另一条业务线（或旧版），**mcspeak 一律用实测码，并把未测到的码当 unknown 处理**。

### 实测原始记录

| 时刻 | 触发 | `orderStatus` | `status` | `pickupCode` | `expirePayTime` |
|---|---|---|---|---|---|
| 18:58:45 | `create-order` | 待支付 | `10` | `""` | 19:13:45 |
| 18:58:51 | `query-order` | 待支付 | `10` | `""` | 19:13:45 |
| **19:14:24** | **超时未付后 `query-order`** | **订单已取消** | **`60`** | **`""`** | 19:13:45（原样保留） |
| — | 历史单 `query-order`（2026-05-24 下单） | **订单已完成** | **`40`** | **`"00000"`**（5 位） | 2026-05-24 13:28:23 |

**超时后没变的字段**：`pickupCode` 仍是空串、`totalAmount`/`realTotalAmount` 仍是 `"33.5"`（**没归零**）、`expirePayTime` 原样保留、`payId` 还在。
→ 也就是说，**光看金额或 pickupCode 判断不了订单是否有效，必须看 `orderStatus`。**

**`pickupCode` 实证**：已完成的历史单是 `00000`（5 位数字字符串），未支付单是 `""`。
→ 取餐码一定是**付款成功后**才产生，且是纯数字字符串（不要当 int，避免前导 0）。

> **★ 请取餐（重点）**：这是唯一需要主动提示访客"现在去拿"的状态，也是**取餐码第一次有值**的时刻。
> 在拿到实测值之前，代码里请用「`pickupCode` 非空」作为"可以去取餐"的**兜底判据**，不要依赖某个魔法数字。

## 2. 麦当劳 App 界面词汇对照表

> 用途：外国游客看不懂 App 上的中文。**取餐卡要放这张表的精简版**（见第 3 节），让他能对着自己的手机屏幕找到按钮。

| 中文原文 | English | 含义 | 用户看到它该做什么 |
|---|---|---|---|
| 待支付 | Awaiting payment | 订单还没付款 | 赶紧付款，超时会作废 |
| 去支付 | Pay now | 付款按钮 | 点它 → 扫码付款（微信/支付宝） |
| 取消订单 | Cancel order | 取消按钮 | 不想买了点这里，未支付取消不扣钱 |
| 联系客服 | Contact support | 客服入口 | 有异常（扣钱没出餐）点这里 |
| 就餐方式 | Dining method | 堂食还是带走 | 核对是「堂食」还是「外带」 |
| 堂食 | Dine-in | 在店里吃 | 找座位，别拿打包袋 |
| 外带 | Takeaway | 点了带走 | 拿到餐就可以走 |
| 预计取餐 | Estimated pickup | 预计什么时候能拿到 | 在这个时间前后去柜台 |
| 餐具需求 | Cutlery | 要不要餐具 | 「不需要餐具」= 没给叉勺，需要就找店员要 |
| 订单编码 | Order number | 订单号（不是取餐码） | 出问题时报给店员/客服 |
| 取餐码 | Pickup code | **取餐用的号码** | **最重要：凭它取餐** |
| 商品小计 | Subtotal | 商品金额 | 核对价格 |
| 合计 | Total | 应付总额 | 核对要付多少 |

### 各状态的英文对照（卡面用）

| 中文 | English | 该做什么（英文） |
|---|---|---|
| 待支付 | Awaiting payment | Pay before {time} or the order is cancelled |
| 配餐中 | Preparing | Wait near the counter |
| 请取餐 | **Ready — collect now** | Show your pickup code at the counter |
| 订单已完成 | Completed | Nothing to do |
| 订单已取消 | Cancelled | Nothing was charged. Order again? |

## 3. 取餐卡精简版（直接印在卡片背面）

> 只放 **7 行**，多了没人看。中文给店员、英文给访客。

```
┌──────────────────────────────────────────┐
│  🍟 取餐码 PICKUP CODE                    │
│        1 2 3 4                            │  ← 字号最大
│                                          │
│  请出示此卡 / Show this card              │
│                                          │
│  待支付 Awaiting payment → 去支付 Pay now │
│  配餐中 Preparing → 请稍等 Please wait    │
│  请取餐 Ready → 可以取餐 Collect now      │
│  已取消 Cancelled → 未扣款，可重新下单     │
│                                          │
│  订单编码 Order no. 1030257900000808...   │
└──────────────────────────────────────────┘
```

**规则**
- **取餐码为空时不要印这张卡**（付款前 `pickupCode=""`），改印「柜台点餐卡」。
- 状态行**只高亮当前那一条**，其余灰掉。
- `订单编码` 用等宽小字，只作申诉用，不要和取餐码混在一起。

## 4. 本地化注意

`orderStatus` 是**中文文字**（如 `待支付`），`status` 是**数字字符串**（如 `"10"`）。

```js
// 正确：先按文字匹配（稳定），再按码兜底
const STATUS = {
  '待支付': { code: '10', key: 'status.unpaid',    action: 'pay' },
  '请取餐': { code: null, key: 'status.ready',     action: 'collect' },  // ★ 待实测补码
  '已完成': { code: null, key: 'status.completed', action: 'none' },
  '已取消': { code: null, key: 'status.cancelled', action: 'reorder' },
  // 未测到的一律落到 unknown：显示原文字 + 通用建议，不猜
};
```

**禁止**：不要用 `status === '10'` 硬编码判断"待支付"之外的含义；码值文档不可信（文档说 10 = 配餐中，实测 10 = 待支付）。

1. **请取餐 / 备餐完成**（★ 最重要，取餐卡就靠它）
